# Embed (chart Part B) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the Embed feature: every answered chart gets an "Embed" button that opens a pop-up with
a piece of `<iframe>` code for pasting into a third-party article; the pasted code loads a public,
no-auth `/embed/[token]` page that renders the chart FROZEN as of the moment it was embedded (default)
or LIVE (Pro accounts only, demoed via an owner-set email allowlist), with the same CBS attribution the
app always shows.

**Architecture:** A signed, stateless HMAC token (`{auditId}.{signature}`) is the only thing that ever
leaves our server — no per-embed database row. `ChartView` (`web/components/chart.tsx`) gains two new
optional props: `embed` (shows the Embed button for the reader's own answered questions) and
`embedMode` (strips every interactive control and shows a frozen/live footer instead) — the SAME
component renders both the normal chat card and the public embed page, so the honesty invariants
(R1/R6/R11, the digit-token scans) automatically cover the embed for free. The public route verifies
the token, loads the immutable audit row, and either renders its stored chart spec unchanged (frozen)
or re-runs the row's stored `StructuredIntent` through the existing deterministic query pipeline
(live, Pro-gated, falling back to frozen on any refusal).

**Tech Stack:** Next.js 15 App Router (TypeScript), React 19, Vitest + `@testing-library/react`,
Node's built-in `crypto` (HMAC-SHA256, `timingSafeEqual`), the existing Recharts-based chart stack —
no new runtime dependency except (optionally) shadcn's `dialog` primitive (Base UI), added the same
way `dropdown-menu` was added in session 90.

**Spec:** [docs/superpowers/specs/2026-09-09-story-mode-and-embed-design.md](../specs/2026-09-09-story-mode-and-embed-design.md)
Part B (§B1–B6) — read it alongside this plan; this plan is the literal build order for that spec.
Also binding: [ADR 038](../../decisions/038-chart-view-state-editing.md) (the reducer this rides on),
[ADR 039](../../decisions/039-chart-presentation-panel.md) (the presentation resolver — Embed adds
ZERO new presentation keys), [docs/05-data-rules.md](../../05-data-rules.md) (R1/R6/R8/R11 — every
number on the embed page must trace to a spec/audit-row string, exactly like the normal chart card).

## Global Constraints

- **Zero LLM calls anywhere in this feature.** The live re-render re-runs a STORED, already-validated
  `StructuredIntent` through the existing deterministic `runQuery`/`buildChartSpec` pipeline — never a
  fresh parse. If validating the stored intent fails for any reason, fall back to frozen; never guess,
  never re-parse the question text with a model (principle (a)/(c), CLAUDE.md).
- **`EMBED_TOKEN_SECRET` and `PRO_ACCOUNT_EMAILS` are owner-set environment variables, set at go-live —
  never by this session, never via `gh secret set`.** Missing `EMBED_TOKEN_SECRET` ⇒ the action returns
  `{ ok: false, reason: 'unavailable' }` and the route 404s. Missing `PRO_ACCOUNT_EMAILS` ⇒
  `hasProPlan` returns `false` for everyone — fail closed, never fail open.
  - **This means the LIVE route path (Task 6) and the go-live smoke test (Task 8) cannot be exercised
    against a real deployed secret by this session — write and unit-test them fully (hermetic, no live
    secret needed), but say plainly in the wrap-up that the actual production smoke test is an owner
    step, not a claim this session can verify.**
- **No new database column, no per-embed table** — `EMBED_TOKEN_SECRET` (stateless HMAC) is the whole
  revocation model: deleting the source chat / GDPR redaction blanks the embed (the audit row's
  `response.redacted` sentinel), rotating the secret blanks every embed at once. Counting only
  (`CHART_STYLE_EVENTS`) rides migration 028, already file-only-pending — the owner's existing
  migration step, not a new one this feature adds.
- **Every new interface string gets both an `nl` and an `en` entry** in `web/lib/i18n/messages.ts`
  (ADR 040) — CBS's own words (units, periods, region names) are never touched by this feature; the
  chart being embedded already carries its own resolved language from when it was created.
  `Messages`/`en` typed from `nl` fails `tsc` on a missing key — that is the safety net, but write both
  every time regardless.
- **The whole-card digit-token scan (`chart.test.tsx`, ADR 039) applies to the embed render too.** Any
  new digit-bearing text this feature adds (the frozen/live footer's date) must be added to that test's
  own whitelist mechanism as a recognised trusted source — never left as an unexplained scan failure
  and never "fixed" by loosening the scan generally.
- **Table form (`state.form === 'table'`) is never embeddable** — the Embed button is hidden exactly
  like Download already is in table form (ADR 039).
- **`docs/` test forbids the literal string `"PR #<n>"`** — write "the PR" in every doc this plan
  touches (session-92 lesson, already in CLAUDE.md).
- **Full verification block before every commit that could land on `main`:** `npm run typecheck` (root

```ts
    expect(verifyEmbedToken(token, OTHER_SECRET)).toBeNull();

  it('rejects an id-substitution tamper (swap the id, keep the old signature)', () => {
    const token = signEmbedToken(42, SECRET);
    const [, sig] = token.split('.');
    expect(verifyEmbedToken(`43.${sig}`, SECRET)).toBeNull();
  });

  it('rejects a single flipped character in the signature', () => {
    const token = signEmbedToken(42, SECRET);
    const [id, sig] = token.split('.');
    const flipped = (sig[0] === 'A' ? 'B' : 'A') + sig.slice(1);
    expect(verifyEmbedToken(`${id}.${flipped}`, SECRET)).toBeNull();
  });

  it('rejects malformed tokens without throwing', () => {
    for (const bad of ['', 'no-dot-here', '42', 'abc.sig', '0.sig', '-1.sig', '42.', '.sig']) {
      expect(verifyEmbedToken(bad, SECRET)).toBeNull();
    }

    expect(() => verifyEmbedToken('42.short', SECRET)).not.toThrow();
    expect(verifyEmbedToken('42.short', SECRET)).toBeNull();
  });

  it('is deterministic — the same id and secret always sign to the same token', () => {
    expect(signEmbedToken(7, SECRET)).toBe(signEmbedToken(7, SECRET));
```

```ts
// src/chart/embed-token.ts
//
// ADR 041 / spec Part B2: a signed, stateless chart-embed token. No database
// row per embed — the token IS the authorization. `{auditId}.{signature}`,
// HMAC-SHA256 over the decimal audit id, signature truncated to 16 bytes and
// base64url-encoded (22 chars, no padding). Verification is constant-time
// (`timingSafeEqual`) and never throws on malformed input — every failure
// mode returns `null`, matching the fail-closed convention `hasProPlan` and
// every other refusal path in this codebase use.
import { createHmac, timingSafeEqual } from 'node:crypto';

const SIGNATURE_BYTES = 16;

function signatureFor(auditId: number, secret: string): string {
  return createHmac('sha256', secret)
    .update(String(auditId))
    .digest()
    .subarray(0, SIGNATURE_BYTES)
    .toString('base64url');
}

export function signEmbedToken(auditId: number, secret: string): string {
  return `${auditId}.${signatureFor(auditId, secret)}`;
}

export function verifyEmbedToken(token: string, secret: string): number | null {
  const dot = token.indexOf('.');
  if (dot < 1) return null;

  const idPart = token.slice(0, dot);
  const sigPart = token.slice(dot + 1);
  if (!/^\d+$/.test(idPart) || sigPart.length === 0) return null;

  const auditId = Number(idPart);
  if (!Number.isSafeInteger(auditId) || auditId < 1) return null;

  const expected = Buffer.from(signatureFor(auditId, secret));
  const actual = Buffer.from(sigPart);
  if (expected.length !== actual.length) return null;
  if (!timingSafeEqual(expected, actual)) return null;

  return auditId;
}
```

```ts
// src/billing/pro.ts
//
// ADR 041 / spec Part B4: "Pro" today is a plain owner-set allowlist — the
// #205 demo switch, since no real Pro plan exists yet. Every caller (the
// embed dialog's `pro` field, the live route's Pro gate) stays unchanged
// when #205 ships a real plan; only this function's body changes. Fails
// closed: an unset env var or a caller with no email is never Pro.
export function hasProPlan(user: { id: string; email: string | null }): boolean {
  const raw = process.env.PRO_ACCOUNT_EMAILS;
  if (!raw || user.email === null) return false;
  const allowed = raw
    .split(',')
    .map((s) => s.trim().toLowerCase())
    .filter(Boolean);
  return allowed.includes(user.email.toLowerCase());
}
```

```ts
// web/app/embed-actions.ts
//
// The signed-in "mint an embed code" Server Action (spec Part B2). Kept to
// its own tiny file, same rationale as chart-style-actions.ts's own header
// comment: chart.tsx (a client component) must never drag this module's
// audit/db graph toward the client bundle by importing chart-style-actions.ts
// and this file from the same barrel.
'use server';

import { loadAuditRecord } from '../backend/answer/audit/index.ts';
import { signEmbedToken } from '../backend/chart/embed-token.ts';
import { hasProPlan } from '../backend/billing/pro.ts';
import { currentUserEmail, currentUserId } from '../lib/current-user.ts';
import { getDb } from '../lib/db.ts';
import { reportError } from '../lib/error-report.ts';

/** The retention redaction sentinel (`src/answer/audit/retention.ts`'s
 * `redactedResponse()`) lives INSIDE the stored response envelope, not as a
 * column on `AuditRecord` — mirrors `scripts/verify-audit-rows.ts`'s own
 * `isRedacted` helper exactly, so a redacted row can never be embedded. */
function isRedacted(response: unknown): boolean {
  return typeof response === 'object' && response !== null && (response as { redacted?: unknown }).redacted === true;
}

export type CreateEmbedCodeResult =
  | { ok: true; token: string; pro: boolean }
  | { ok: false; reason: 'unauthenticated' | 'not_found' | 'forbidden' | 'unavailable' | 'error' };

export async function createEmbedCode(auditId: number): Promise<CreateEmbedCodeResult> {
  const userId = await currentUserId();
  if (userId === null) return { ok: false, reason: 'unauthenticated' };

  const secret = process.env.EMBED_TOKEN_SECRET;
  if (!secret) return { ok: false, reason: 'unavailable' };

  try {
    const record = await loadAuditRecord(getDb(), auditId);
    if (record === null) return { ok: false, reason: 'not_found' };

    if (
      record.userId !== userId ||
      record.response.kind !== 'answer' ||
      record.response.chart === null ||
      isRedacted(record.response)
    ) {
      return { ok: false, reason: 'forbidden' };
    }

    const email = await currentUserEmail();
    const pro = hasProPlan({ id: userId, email });
    return { ok: true, token: signEmbedToken(auditId, secret), pro };
  } catch (e) {
    await reportError('createEmbedCode', e, { userId, auditId });
    return { ok: false, reason: 'error' };
  }
}
```

```tsx
// web/components/chart-embed-dialog.tsx
'use client';

import { useEffect, useRef, useState } from 'react';
import { createEmbedCode } from '../app/embed-actions.ts';
import { recordChartStyleEvent } from '../lib/chart-usage-client.ts'; // confirm real path/name (Step 1 note)
import { useT } from '../lib/i18n/lang-provider.tsx';
import type { Lang } from '../lib/i18n/messages.ts';
import { Button } from './ui/button.tsx';

const APP_URL = process.env.NEXT_PUBLIC_APP_URL ?? 'https://checkdecijfers.nl';

type ColourOption = 'light' | 'dark' | 'auto';
type ChartTypeOption = 'as-shown' | 'default';

function buildEmbedCode(
  token: string,
  opts: { lang: Lang; colour: ColourOption; chartType: ChartTypeOption; currentForm: string | null; live: boolean },
  title: string,
): string {
  const params = new URLSearchParams({ lang: opts.lang, theme: opts.colour });
  if (opts.chartType === 'as-shown' && opts.currentForm) params.set('form', opts.currentForm);
  if (opts.live) params.set('live', '1');
  return `<iframe src="${APP_URL}/embed/${token}?${params.toString()}" width="100%" height="440" title="${title}" loading="lazy" style="border:0"></iframe>`;
}

export function ChartEmbedButton({
  auditId,
  tableId,
  lang,
  currentForm = null,
}: {
  auditId: number;
  tableId: string;
  lang: Lang;
  /** The chart's currently-displayed form (e.g. 'line'/'bar'), for the
   * "As shown" option — null when the caller doesn't track it, in which
   * case "As shown" degrades to the spec's own default (same as omitting
   * `form` from the query string). */
  currentForm?: string | null;
}) {
  const t = useT();
  const [open, setOpen] = useState(false);
  const triggerRef = useRef<HTMLButtonElement>(null);

  return (
    <>
      <Button ref={triggerRef} type="button" variant="ghost" size="sm" onClick={() => setOpen(true)}>
        {t('chart.embed.trigger')}
      </Button>
      {open ? (
        <ChartEmbedDialog
          auditId={auditId}
          tableId={tableId}
          lang={lang}
          currentForm={currentForm}
          onClose={() => {
            setOpen(false);
            triggerRef.current?.focus();
          }}
        />
      ) : null}
    </>
  );
}

function ChartEmbedDialog({
  auditId,
  tableId,
  lang,
  currentForm,
  onClose,
}: {
  auditId: number;
  tableId: string;
  lang: Lang;
  currentForm: string | null;
  onClose: () => void;
}) {
  const t = useT();
  const [result, setResult] = useState<{ token: string; pro: boolean } | 'loading' | 'unavailable'>('loading');
  const [embedLang, setEmbedLang] = useState<Lang>(lang);
  const [colour, setColour] = useState<ColourOption>('light');
  const [chartType, setChartType] = useState<ChartTypeOption>('as-shown');
  const [live, setLive] = useState(false);
  const [copied, setCopied] = useState(false);
  const dialogRef = useRef<HTMLDivElement>(null);

  useEffect(() => {
    let cancelled = false;
    createEmbedCode(auditId).then((r) => {
      if (cancelled) return;
      setResult(r.ok ? { token: r.token, pro: r.pro } : 'unavailable');
    });
    void recordChartStyleEvent('embed_open');
    return () => {
      cancelled = true;
    };
  }, [auditId]);

  const code =
    result === 'loading' || result === 'unavailable'

  return (

        <h2 className="text-sm font-medium">{t('chart.embed.dialogTitle')}</h2>
        <p className="mt-1 text-xs text-muted-foreground">{t('chart.embed.dialogExplain')}</p>

        {result === 'loading' ? <p className="mt-3 text-xs text-muted-foreground">{t('chart.embed.loading')}</p> : null}
        {result === 'unavailable' ? <p className="mt-3 text-xs text-destructive">{t('chart.embed.unavailable')}</p> : null}

          <>

              <legend className="text-xs text-muted-foreground">{t('chart.embed.languageLabel')}</legend>
              <label className="mr-3 text-xs">
                <input type="radio" name="embed-lang" checked={embedLang === 'nl'} onChange={() => setEmbedLang('nl')} /> NL
```

```ts
// src/chart/embed-live.ts
//
// ADR 041 / spec Part B3 "Live" mode: re-running a STORED StructuredIntent
// through the live pipeline. `AuditRecord.intent` is typed `unknown` on
// purpose (it's promoted, freeform JSON) — this is the one place in the
// codebase that trusts it enough to call `runQuery`, so it validates
// defensively by hand (the same style as chart-style-actions.ts's
// `parseBrandApplied`), never with a bare cast. Any shape surprise returns
// null, and `rerunLive` below turns every null/refusal/thrown-error case
// into the same "fall back to frozen" signal the route already has to
// handle for a missing table — one code path, not two.
import { buildChartSpec } from './build.ts';
import { runQuery } from '../query/run.ts';
import type { Db } from '../db/types.ts';
import type { AuditRecord } from '../answer/audit/types.ts';
import type { IntentDerivation, IntentPeriod, IntentTarget, StructuredIntent } from '../query/types.ts';
import { INTENT_SCHEMA_VERSION } from '../query/types.ts'; // adjust the import if this constant lives
// under a different exported name — grep it first.
import type { Lang } from '../../web/lib/i18n/messages.ts'; // adjust the relative path to whatever this
// module's real location resolves to against web/lib — confirm with the existing cross-imports other
// src/chart files already make into web/lib (e.g. chart-presentation.ts's own Lang import), and mirror
// that exact path style rather than inventing a new one.

function isValidTarget(v: unknown): v is IntentTarget {
  if (typeof v !== 'object' || v === null) return false;
  const t = v as Record<string, unknown>;
  if (t.kind === 'canonical') return typeof t.key === 'string';
  if (t.kind === 'explicit') return typeof t.tableId === 'string' && typeof t.measure === 'string';
  return false;
}

function isValidPeriod(v: unknown): v is IntentPeriod {
  if (typeof v !== 'object' || v === null) return false;
  const p = v as Record<string, unknown>;
  if (p.kind === 'codes') return Array.isArray(p.codes) && p.codes.every((c) => typeof c === 'string');
  if (p.kind === 'range') return typeof p.from === 'string' && typeof p.to === 'string';
  return false;
}

const VALID_DERIVATIONS: readonly IntentDerivation[] = ['none', 'difference', 'max', 'series'];

export function parseStoredIntent(raw: unknown): StructuredIntent | null {
  if (typeof raw !== 'object' || raw === null) return null;
  const r = raw as Record<string, unknown>;

  if (r.schemaVersion !== INTENT_SCHEMA_VERSION) return null;
  if (!isValidTarget(r.target)) return null;
  if (!isValidPeriod(r.period)) return null;
  if (typeof r.derivation !== 'string' || !VALID_DERIVATIONS.includes(r.derivation as IntentDerivation)) return null;
  if (r.regions !== undefined && !(Array.isArray(r.regions) && r.regions.every((x) => typeof x === 'string'))) {
    return null;
  }

  return {
    schemaVersion: r.schemaVersion,
    target: r.target,
    period: r.period,
    derivation: r.derivation as IntentDerivation,
    ...(r.regions !== undefined ? { regions: r.regions as string[] } : {}),
  } as StructuredIntent;
}
```

### Task 7: Framing headers (`next.config.ts`)

**Files:**
- Modify: `web/next.config.ts`
- Test: `web/next.config.test.ts`

**Interfaces:**
- Produces: nothing another task consumes — this is a leaf, purely for the browser's own framing
  security model. Order-independent of every other task; could run any time after Task 5 exists (so
  the embed path is real when this is tested), but has no code dependency on it.

**Why this matters and the risk to get right:** every OTHER route in this app must keep
`X-Frame-Options: DENY` (clickjacking protection) — ONLY `/embed/:path*` may be framed. Next.js applies
ALL matching `headers()` entries for a request path; for the SAME header key matched by two entries,
the LATER entry in the returned array wins. Getting the `source` patterns wrong in either direction is
a real security regression (leaving the whole app framable) or a real feature break (the embed refusing
to render inside a reader's `<iframe>`) — this task's test must prove the intended behavior on DATA, and
the go-live smoke test (Task 8) must prove it again on a REAL deployed response, because a `source`
pattern mistake a unit test misses is exactly the kind of thing that only shows up live.

- [ ] **Step 1: Write the failing test**

```ts
// web/next.config.test.ts
import { describe, expect, it } from 'vitest';
import nextConfig from './next.config.ts';

describe('framing headers (ADR 041)', () => {
  it('exports an async headers() function', () => {
    expect(typeof nextConfig.headers).toBe('function');
  });

  it('denies framing by default (X-Frame-Options: DENY, CSP frame-ancestors none)', async () => {
    const groups = await nextConfig.headers!();
    const catchAll = groups.find((g) => g.source !== '/embed/:path*');
    expect(catchAll).toBeDefined();
    const byKey = Object.fromEntries(catchAll!.headers.map((h) => [h.key, h.value]));
    expect(byKey['X-Frame-Options']).toBe('DENY');
    expect(byKey['Content-Security-Policy']).toContain("frame-ancestors 'none'");
  });

  it('permits any-origin framing on /embed/:path*, and does NOT also send X-Frame-Options: DENY there', async () => {
    const groups = await nextConfig.headers!();
    const embedGroup = groups.find((g) => g.source === '/embed/:path*');
    expect(embedGroup).toBeDefined();
    const byKey = Object.fromEntries(embedGroup!.headers.map((h) => [h.key, h.value]));
    expect(byKey['Content-Security-Policy']).toContain('frame-ancestors *');
    expect(byKey['X-Frame-Options']).toBeUndefined();
  });

  it("the catch-all source pattern does not itself match /embed paths (so DENY can never win there)", () => {
    // A cheap, direct proof independent of Next's own path-to-regexp version: compile the exact
    // catch-all `source` string this file uses with the SAME `path-to-regexp` package Next bundles
    // (it's a transitive dependency already in node_modules — `require.resolve('next/dist/compiled/path-to-regexp')`
    // or just `path-to-regexp` if it resolves directly) and assert it does NOT match `/embed/abc123`
    // and DOES match `/`, `/login`, `/credits`. This is the one case in this task worth spending
    // real effort on getting right, because it is the exact mechanism a wrong regex would silently
    // break — don't skip it even though it's more invasive than the others.
  });
});
```
