# ADR 044 — The Story stage: the Insights story as a full-screen, scroll-driven presentation

**Status:** accepted in design, 2026-09-11 (session 95, autonomous overnight — the owner's kickoff pre-resolved the plan's decisions: "3D" = depth/tilt/motion around a FLAT chart, never 3D marks or the map; zero new libraries; auto-play off by default; spotlight only, no zoom). **Build state: see [STATUS.md](../STATUS.md) — this ADR records the decision; the as-built addendum at the end says how far the build got.** Plan: [superpowers/plans/2026-09-11-story-stage-v1.md](../superpowers/plans/2026-09-11-story-stage-v1.md). Spec: [session-briefs/2026-09-10-visual-next-level-plan.md](../session-briefs/2026-09-10-visual-next-level-plan.md) §3.

## Context

The owner's session-94 words: "Story mode is the one, I would say, with the 3D thing, scroll effects, etc." Today's Insights panel (ADR [041](041-chart-insights.md), on the session-92 story mechanism in ADR [039](039-chart-presentation-panel.md)) is the scrollytelling skeleton inverted: the chart sits still in the chat column and the steps scroll inside a 160 px box under it — right for a chat answer, but a stepper, not a stage. The genre (The Pudding, the NYT/Bloomberg graphics desks, Flourish stories) pins the graphic and scrolls the text past it. The reference demo turned out to be a 3D municipality MAP with a scroll story (plan §12) — a different, geographic feature; the kickoff ruled it out for this programme because a 3D chart makes equal values look unequal (Tufte, Cleveland–McGill) and a WebGL canvas is invisible to every honesty scan and to the export (R6). Constraints: R1/R6/R11 in every frame (no non-spec digit, the hollow ring always visible, transforms only on wrappers outside the exported `<svg>`); no library (Option A: CSS 3D + a scroll hook, 0 kB); no LLM/API/schema change; `prefers-reduced-motion` honoured; the compact panel keeps working unchanged.

## Decision

1. **A second layout of the same story, not a second story.** "Presenteren / Present" on the Insights panel opens a full-viewport overlay (`ChartStoryStage`): `position: fixed; inset: 0`, `role="dialog" aria-modal="true"`, focus moved in, Escape and a Close button close it and return focus to the Present button, the page scroll locked meanwhile. A portal into `document.body` for POSITION only; open/index state lives in `ChartView` exactly like the compact panel's (the session-91 lesson: lift state, never portal to move controls). The same `storySteps` (findings, AI-phrased captions when they have arrived) and the same `storyIndex` drive both layouts; a step change in the stage flows through the existing `onStoryIndexChange`.
2. **The chart in the stage is a second `ChartView` instance in stage mode** (`stage: { step, overrides }`): chrome-less (no form tabs, no Style/Insights triggers, no Vanaf/Tot, no notes, no small multiples, no Download, no legend buttons — legend chips only; **as built, the review round also drops the definition line and the trend headline**: the step's own caption is the sentence being presented, while the caveats that carry data-quality meaning — the null notes, the provisional sentence and its marker key, the event-marker notes — and the source line always stay. A many-series spec that would open on the table in the chat opens on the CHART here, since the stage has no form tabs to switch back with), wearing the chat chart's current per-chart overrides (a template included), and driven ONLY by the given step (highlight + the existing dashed ring). It holds no reader state, so there is nothing to leak or restore (the session-79/89 cross-instance lessons). The chat's own chart never moves (the dock is `overflow-hidden`; moving DOM means a remount anyway).
3. **Layout.** ≥ `lg`: the chart column (55 %) sticky and vertically centred, the steps column scrolls with one `min-h-[85vh]` panel per finding; < `lg`: the chart pinned in at most the top 50 % of the viewport — a MAXIMUM that scrolls internally when the card is taller, not a fixed height (as built, review round: a fixed height clipped the caveats and the source line off the bottom on a phone) — the steps beneath, `touch-pan-y` kept.
4. **"3D" = depth and motion around a flat chart.** On entry the chart plane sits at `perspective(1200px) rotateX(8deg)` (below the spec's 12° cap) lifted with a deep shadow, and settles flat over the scroll from the top of the steps column to the moment the FIRST caption reaches the viewport centre (as built, review round: its own continuous `entryProgress` ramp, not the nearest-centre step `progress`, which caps at ~0.5 and made the plane pop 4°→0° at the first boundary with the first finding still tilted) — the tilt exists only while no number is being read; from there on the plane is flat. Captions fade and rise into place as their panel nears the viewport centre. Below `lg`, on `(hover: none)`, or with `prefers-reduced-motion: reduce`: no tilt, no shadow animation, instant step switches (highlight + ring still work — WCAG 2.3.3, mandatory).
5. **Camera = spotlight, no pan, no zoom.** For a point step the stage reads the ringed marker's position ONCE per step change (never per frame) — plus once per resize tick, since Recharts measures itself asynchronously and the first step otherwise came up with no vignette at all (as built, review round) — and centres a radial vignette on it, confined to the PLOT box so the title, the legend and the source line are never dimmed; the existing dimming and dashed ring do the rest. The spec's translate-to-centre pan was dropped for v1: moving the whole svg pushes axis and value labels off the card at small widths, and the vignette + ring already say "here" without moving a single number. Zoom stays a v2 owner decision (the spec's honesty note).
6. **Scroll → step** through one rAF-throttled `scroll` listener and the pure `stageProgress` (the panel whose centre is nearest the viewport centre wins; a 0–1 progress toward the next feeds the entry tilt and caption reveal). Programmatic scrolls (dots, arrow keys, auto-play) open a 150 ms settle window the listener ignores — the compact panel's settle-guard idea. IntersectionObserver is not used here: the stage needs continuous progress, not membership. Native scroll-driven CSS animations are not used in v1 (uneven support; the hook is the universal path).
7. **Auto-play** is a toggle, OFF by default (kickoff decision 7): every four seconds to the next step, stopping at the last or on any user scroll/key; counted once per activation (`stage_autoplay`). `stage_open` counts each opening. Both on the anonymous counter (nothing recorded until migration 028 is applied).
8. **Digit-free chrome, both languages**: Presenteren/Present, the dialog label, Sluiten/Close, "Scroll om verder te gaan"/"Scroll to continue", Automatisch afspelen/Auto-play, Stappen/Steps; positions are dots, never "N of M". The whole-card digit scan runs over `document.body` with the stage open.
9. **Nothing in the stage exports, persists or costs**: no Download in the stage (the chat chart's export is unchanged), no state written anywhere, no LLM call added (the phrased captions already arrive through the compact panel's flow), no embed (the stage is not offered inside an embed; "story in the embed" stays ADR 041's follow-up).

## Alternatives considered

- **Charts drawn as 3D objects (extruded bars, an orbiting camera, Three.js).** Rejected — the plan's §3.2 case: perspective makes equal values look unequal; a canvas is opaque to the R1/R6 scans, to screen readers and to the svg export; a second renderer with its own honesty proofs is a different product with a weaker guarantee. Three.js as a decorative backdrop remains a measured escalation gated on `stage_open` data and an explicit owner bundle OK.
- **The 3D municipality map** (what the reference demo actually is). Out of scope for this programme — a geographic feature, not a chart enhancement; a written proposal at most, once everything else is done.
- **GSAP + ScrollTrigger.** Held as the measured escalation if the hand-rolled scrub stutters on real devices; the pure functions do not change, only what drives them.
- **Framer Motion / `motion`.** Rejected: animating Recharts' own paths fights the library and could put a half-drawn state in an export — the exact reason Recharts animation was refused.
- **Growing the chat's chart in place instead of an overlay.** Rejected: the dock is `overflow-hidden`, pinning inside a scrolling column is fragile, and the reader would lose the conversation behind it.
- **Pan/zoom to the step's point.** Dropped for v1 (decision 5); zoom is a v2 owner decision.

## Consequences

- One new overlay component, one hook, one pure module, a `stage` prop on `ChartView` with about a dozen `inStage` gates; zero bundle growth from dependencies.
- Two `ChartView` instances render the same spec while the stage is open — a few milliseconds of Recharts work; acceptable (the homepage already renders five).
- The stage instance shows the spec's default form (line / bar), not a form the reader switched to in the chat (v1 simplification).
- The real proof is a browser, not jsdom: scroll, tilt, the vignette, the phone layout and both themes are checked on the dev server in the Browser pane before the phase is called done; jsdom pins the pure functions, the dialog semantics, the digit scans and the auto-play timer.

## Revisit triggers

- `stage_open` counts (after migration 028) justify the effort of pan/zoom (v2), per-series camera moves for multi-series stories, or a lazy-loaded decorative backdrop (explicit owner bundle OK).
- The hand-rolled scrub stutters on a mid-range phone → GSAP for the stage only.
- Native scroll-driven CSS animations reach Safari and Firefox stably → replace the hook where it deletes code.

## As built — 2026-09-11, session 95 (autonomous), branch `visual-story-stage`

Built through Subagent-Driven Development (five tasks, a reviewer per task, a fable whole-branch review, one fix wave, a scoped re-review, one post-loop two-line fix). What the code does today, where it differs from the decision text above, and what is parked:

- **Motion, as built.** The entry tilt is 8° with a lifting shadow; it settles FLAT over `entryProgress` = how far the reader has scrolled toward the FIRST caption's centre, so the plane is flat before the first finding is read (the review found that the original "settle over the first step's progress" left the first caption — a number — on a tilted plane; `stageProgress`'s nearest-centre progress also caps at ~0.5 and popped at each boundary). Captions reveal continuously (`2·progress` / `1 − 2·progress`); programmatic jumps ease (`transform` in the transition). The whole motion set is OFF (flat plane, no vignette, instant switches) below `lg` (1024 px), on `(hover: none)` and under `prefers-reduced-motion` — a lazy-initialised `useStageMotion()`. **There is no parallax in v1** — the plan's three layers were not built.
- **Spotlight, as built.** Read once per step change AND on a ResizeObserver tick of the chart box (Recharts has not measured at the moment the stage opens), confined to the plot box (`[data-slot="chart-frame"]`) so the title and the R4 attribution are never washed. No pan, no zoom.
- **Opening at the current step.** Opening from step N scrolls panel N into view; the hook→index sync applies only after a real reader gesture (wheel/touch/pointer/scroll/key), so a mount-time index-0 report never resets the reader's step.
- **Auto-play** stops on any reader gesture (wheel, touch, pointer-down, an unhandled key) and on close; `stage_autoplay` is counted outside the state updater (Strict Mode safe). The scroller's own `scroll` event only arms the reader-scroll guard — it never stops auto-play, because auto-play's own advance (`go()` → `scrollIntoView`) fires `scroll` on that same element; the post-loop fix that bound `scroll` to the shared gesture handler made auto-play switch itself off after its first advance in a real browser (jsdom stubs `scrollIntoView`, so the suite stayed green). Found by the mandatory `/code-review` LOW pass after three review seats had passed it; fixed with a pinned test that dispatches a bare `scroll` between two timer advances. **Mostly fixed 2026-09-11 (session 96, see the addendum below):** `useStageScroll` now exposes `isProgrammatic()`, and the scroll listener stops auto-play on any scroll that isn't the stage's own — closing the scrollbar-drag case for the common, isolated case. Residual, narrower gap, accepted: `isProgrammatic()` is a time-window read, not a per-event cause read, so a drag that overlaps an in-flight programmatic scroll (auto-play's own `scrollIntoView`, a dot/key jump still easing) keeps the same settle window open and is not distinguished from that programmatic scroll until it pauses.
- **The compact panel's IntersectionObserver is a no-op while the stage is open** (a classic-scrollbar reflow could otherwise overwrite the shared step). Parked: the reverse reflow on CLOSE can still make the compact observer snap the step (pre-existing behaviour of the compact panel).
- **Stage-mode chart:** the spec's own form (line / bar), never the table, even for a > 15-series spec; hides the definition line and the trend headline (explanatory prose without numbers — the phone layout needed the room); keeps the null-cell notes (R11), the provisional sentence + marker key, the event-marker notes (#170(4)), the attribution + source badge (R4); the export container drops its `tabpanel` role (no tablist in the stage).
- **Phone layout:** the pinned area is `max-h-[50vh] overflow-y-auto` with `items-start` and the card `my-auto`, so a card taller than half the viewport scrolls inside its area and its top stays reachable (the fix wave's first attempt used `items-center`, which clips the top of a scroll container — caught in re-review).
- **Focus:** Tab/Shift+Tab wrap inside the dialog (the dialog is the Shift+Tab anchor); Escape from any inner element closes and returns focus to the Present button; the page scroll lock is restored on every close path.
- **Parked (minor, recorded here so they are not lost):** the rects are read while the plane may still be tilted (a few px on a soft gradient, self-corrects on the next step); `readSpot` re-renders the stage on every resize tick (no equality bail-out); the desktop entry ramp is short in practice (~120 px, the first caption sits close to the viewport centre); the hook keeps `programmatic` semantics per open; the plan file `2026-09-11-story-stage-v1.md` still carries its original snippets (a frozen input — this addendum records every deviation).
- **Verification:** see [STATUS.md](../STATUS.md) for the measured numbers. A real-browser pass ran before the fix wave (desktop light + dark; the phone overflow defect that led to the phone rules above), and **the post-fix re-check ran on the final code** in the session's browser pane against the dev server (after diagnosing why the hidden pane showed no charts — React 19's streaming reveal waits on `requestAnimationFrame`, which never fires in a hidden tab; see lessons-learned): opening Present from finding 3 lands on finding 3 (panel centred, ring on its point, body scroll locked, focus inside); a slow scroll across the 3→4 boundary crossfades the captions continuously (1 → 0.66 → 0.31 → 0.3 and 0.3 → 0.64 → 0.99 → 1) with the plane flat throughout and the ring switching at the midpoint; auto-play from finding 1 advances 1 → 2 → 3 across a `scroll` event (the bug above, fixed), stops on a wheel event, and switches itself off at the last finding; Escape closes, returns focus to the Present button and releases the scroll lock with the compact panel still open; phone 375 px: the pinned area is exactly 50vh with `overflow-y: auto`, the 444 px card scrolls inside it with its top at 0, no horizontal overflow, no tilt (the `(hover: none)` / `< lg` gate); dark mode legible. Not checked: a page with classic (always-visible) scrollbars, and smooth-scroll motion itself (a hidden tab does not animate). One as-built detail seen: opening at finding N shows the 200 ms settle from 8° to flat (the hook's first measurement lands after the first paint) — accepted.

## Addendum — 2026-09-11, session 96: motion/atmosphere upgrade, branch `visual-story-motion`

The owner's explicit ask, after an initial too-small first attempt: make the stage genuinely impressive, not just competent. Built as a small sequential chain of subagents (each in its own worktree, later merged in order), with the orchestrating session doing the design/scoping and a real-browser check (a throwaway debug route, `web/proxy.ts` allowlisted temporarily and reverted) before shipping — jsdom cannot see any of this.

- **Auto-play/scrollbar-drag fix** (small, independent): see the "Mostly fixed" note above.
- **Plane "breathing" drift** (`planeDriftPx`/`planeTransform`, `chart-stage.ts`): a small (5px peak) continuous `translateY` on the chart plane between steps, `Math.sin(progress·π)·5`, 0 at both ends of a step — never a rotation, never a pan toward a marker (decisions 4/5 stand unchanged). Gated on the same `staticMotion` as everything else.
- **Ambient atmosphere layer** (`atmosphereState`, `chart-stage.ts`; `data-stage-atmosphere`, `chart-story-stage.tsx`): a decorative, `aria-hidden` background of two large blurred blobs behind the whole dialog, tinted to the active finding's own series colour via the real `seriesColor()` resolver — never an invented colour — at reduced intensity for overview steps. Establishes `--stage-accent`, a CSS custom property on the dialog root, as the shared colour source every later piece (captions, spotlight) reuses rather than re-deriving its own. Colour transitions via `background-color` only (not the gradient itself — cross-browser gradient interpolation is unreliable, the same lesson the spotlight rewrite below independently reached). The `<style>` tag carrying the keyframes is portalled into `document.head`, not `document.body` — the whole-body digit scan (`chart.test.tsx`) walks text nodes, and a `<style>` tag's own CSS text (its keyframe percentages/durations) is a real DOM text node that would otherwise fail it.
- **Editorial captions** (`captionStyle`, `chart-stage.ts`; the caption block, `chart-story-stage.tsx`): title `text-3xl`→`sm:text-4xl`→`md:text-5xl` (was `text-base`), body scaled to match; the bordered `bg-card` box is gone — captions sit directly over the atmosphere layer, legibility guaranteed by a borderless `bg-background/70 backdrop-blur-md` scrim behind the text via a negative inset (provably ≤ ~10% accent contamination can reach the pixels behind any letterform, given the atmosphere layer's own 30% cap — see the code comment for the exact math). `captionStyle` gained a blur (`filter`) and scale term on top of the existing opacity/translateY, all driven by the same `distance` input, all exactly neutralised under reduced motion. A small `--stage-accent` rule above each title is the only colour tie.
- **Spotlight motion** (`spotlightGlowStyle`, `chart-stage.ts`; the spotlight block, `chart-story-stage.tsx`): the vignette used to snap instantly to a new marker. Split into an outer confinement div (unchanged plot-box geometry — the "never over the attribution" guarantee is untouched) and an inner glow now positioned via `transform: translate3d(...)`, eased 400ms `cubic-bezier(0.34, 1.56, 0.64, 1)` (ease-out-back) — the overshoot itself reads as an arrival flourish, so no separate pulse was added. Colour now mixes `var(--stage-accent)`, replacing an independently-derived one.
- **A real mobile regression, caught only by the real-browser check and fixed before shipping:** the steps column had `lg:pt-[20vh]` top padding but none below `lg` — harmless with the old opaque bordered cards, but the new borderless captions' negative-inset scrim could bleed up into the sticky pinned chart's own attribution line when `scrollIntoView({block:'center'})` centred a panel close to the 50vh sticky boundary on a phone. Fixed with `scroll-mt-[52vh] lg:scroll-mt-0` on each step panel (a purpose-built CSS property for exactly this "sticky header overlaps scrolled-to content" problem), confirmed fixed by a second screenshot.
- **Confirmed harness quirk, not a product bug:** three independent worktree-isolated subagents in this chain each found their fresh worktree was not actually on the intended shared branch (it started on a scratch branch pointing at plain `main`) — each caught it via an explicit instruction to check `git log` for named prior commits before writing code, and re-branched by name. Worth expecting on any future multi-agent chain that depends on a shared, evolving base branch.
- **Verification (measured):** root + web typecheck clean; web suite 94 files / 1479 tests; backend suite 143 files / 2211 tests; hermetic benchmark 28/28; `test:docs` 11/11; real `next build` clean; `/code-review` LOW — 0 findings. Real browser (a throwaway fixture route, both themes, desktop 1280px + phone 375px, reduced motion): atmosphere tint and spotlight easing visible and subtle (not garish) in both themes; editorial typography reads clearly larger/bolder; the mobile overlap above found and fixed. Not checked: a real device (only a headless-Chromium viewport emulation), Safari/Firefox rendering, an actual multi-series/many-series spec.
