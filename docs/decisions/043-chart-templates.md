# ADR 043 — Chart templates v1: named looks over the presentation overrides

**Status:** accepted, 2026-09-11 (session 95, autonomous overnight — the owner's kickoff pre-resolved "templates v1 = looks only, starter charts are v2"). Built on branch `visual-templates-v1`, stacked on the ADR [042](042-designed-default-chart.md) branch; a pull request is open for the owner's review per CLAUDE.md #118(b). Plan: [superpowers/plans/2026-09-11-chart-templates-v1.md](../superpowers/plans/2026-09-11-chart-templates-v1.md). Spec: [session-briefs/2026-09-10-visual-next-level-plan.md](../session-briefs/2026-09-10-visual-next-level-plan.md) §5.

## Context

The owner's session-94 ask, in his words: "we can offer … premade templates. People can select templates and build upon them, but they can also start by chatting." The ICP — freelance journalists and small newsrooms on deadline — needs a publication-ready look in one click, not a design tool. ADR [039](039-chart-presentation-panel.md) had already reserved the seam ("presets remain possible later as named `Partial<ChartPresentation>` objects over the same overrides"), and ADR 042 had just made a designed default the base every chart resolves on top of. Constraints: no spec change, no audit change (a template is presentation, never data — ADR 039's alternative 3), no schema, no LLM, no library (cheapest mechanism first); every honesty lock re-runs per render whatever a template says; the Style panel stays a dumb component; owner decision E (each chart starts fresh; the account default is the only persistence) stays intact.

## Decision

1. **A template is a code constant** in `web/lib/chart-templates.ts`: `{ id, nameKey, descriptionKey, overrides: PresentationOverrides }`. Six looks, in this order: **Basis/Standard** (the designed default), **Klassiek/Classic** (the session-87 Recharts look including its palette, via `seriesColors` by index), **Redactie/Newsroom** (3 px line, no markers but the honesty ring, horizontal grid, no axis lines, value labels, small padding, 16:9 — the ICP's publish-ready look), **Presentatie/Presentation** (dark slate gradient, inset card, medium padding, rounded, strong shadow, 16:9, 3 px), **Sociaal/Social** (the `ocean` preset, inset card, very rounded, soft shadow, 4:5, 3 px, value labels), **Minimaal/Minimal** (no grid, no axis lines, no markers but the ring, value labels). Every template survives `sanitizeOverrides` byte-identical (test-pinned) — a key the resolver does not know is a bug, not a silent drop.
2. **Basis applies the designed default EXPLICITLY** — every `STOCK_PRESENTATION` key except `seriesColors`, `fontFamily` and `language`, derived from the constant. The plan first proposed `{}`; the whole-branch review showed that `{}` merely resets to the resolver's *base*, which for a signed-in user is their saved account default, so Basis would be a no-op for exactly the users who saved a Classic-shaped default. With the explicit values, a signed-in user who presses Basis sees the designed default and the "Standaard" button lights up (= back to *my* default) — coherent. Saving that as the account default stores the explicit stock keys, which is harmless.
3. **Applying = `resetPresentation` then `setPresentation(template.overrides)`** in `chart.tsx`, plus clearing the uploaded frame image (like the full reset) and one counter event `template_<id>` (six typed events on the anonymous counter; a template pick deliberately does NOT also fire `option_changed` — "which look" and "which control" are different questions; the counter records nothing until the owner applies migration 028). A template replaces the reader's per-chart tweaks: a look is a whole, not a layer. The resolver's locks then re-run per render exactly as for a hand-picked value, so a template can never switch value labels off on a bar chart, hide a provisional marker or move a baseline (pinned: `minimal` × bar keeps value labels shown and the zero baseline).
4. **Design-time contrast gate, as a test:** every template × every `DEFAULT_PALETTE` colour (Classic: `RECHARTS_PALETTE`) × that template's own backdrops (`frameBackdrops` of its resolved values) → no `judgeColorAgainst` refusal. The two templates with coloured backgrounds use the inset card, so their backdrops are the card colours by construction — and the inset card is what `ChartFrame` draws on screen and what the export's framed path draws (white in the export, which resolves against the light theme per #222: on screen in dark mode the card is dark, in the file it is white — both backdrops are inside the gate).
5. **"Current" template = the most specific template whose every override equals the effective value** (`matchTemplate(values)`); a tweaked chart matches nothing (honest: it no longer wears that look); a pristine chart with a Classic-shaped account default is marked Klassiek. Ties on key count fall to roster order (no two templates can tie on real values today — their frame values conflict). Equality is `JSON.stringify` per key — fine for the enum values and for `frameBackground`, whose key order zod fixes.
6. **The Sjablonen/Templates tab is FIRST in the Style panel's tab order but the panel still opens on Grafiek** — opening on Templates would have changed the flow of some forty existing tests and the reader's muscle memory in one go; first position already puts the gallery where the eye is. Revisit on counter data.
7. **The gallery is a radiogroup** (`role="radiogroup"`, cards `role="radio"` + `aria-checked`, a roving tab stop on the current card or the first, arrow keys through the panel's shared handler — which, like every other radiogroup in the panel, also applies the focused card): "exactly one of six is current" is radio semantics, and the whole-branch review rejected the first build's `aria-pressed` toggle buttons (pressing a pressed toggle implies un-pressing). The card's accessible name is exactly the template name (`aria-label`), the "Huidig/Current" badge and the description live inside it without polluting the name.
8. **Thumbnails are derived, not drawn:** `TemplateThumb` resolves the template's own overrides and draws background/inset/corners, horizontal and vertical grid lines, axis lines or the hairline baseline, the marker mode (all / ends / none), the line weight and the first series colour over one fixed polyline — no `<text>`, `aria-hidden`, so it cannot drift from what the template applies and cannot put a digit on screen.
9. **Brand is a card, not a template:** shown only for a signed-in visitor (the `brand` prop), its button switches the panel to the Colours tab where "Pas merkkleuren toe" already lives. The spec (§5.2) suggested "disabled with its reason when the key is absent"; this build leaves key-gating to the Colours tab (one place, one reason) — a deliberate deviation.
10. **Copy** lives in `messages.ts` in both languages, digit-free (descriptions say "staand formaat" / "portrait", never "4:5"); Basis is not called "Standaard" and Standard is not called "Default" because those are the reset button's names.

## Alternatives considered

- **Templates in the spec or the audit row.** Rejected as ADR 039 already did: presentation never enters the spec; the same chart must stay reproducible from its audit row whatever look it wore.
- **Starter charts (a curated chart + a look) in v1.** Deferred to v2 by the kickoff (decision 3): each starter is a hand-curated intent over the homepage's curated path — bounded, zero-LLM, but a separate slice.
- **Opening the panel on the Templates tab.** Rejected for v1 (decision 6).
- **`{}` as Basis.** Rejected in review (decision 2).
- **Toggle buttons (`aria-pressed`) for the cards.** Rejected in review (decision 7).
- **A browser-remembered template for anonymous visitors** (spec §5.2 entry point 2). Not built: owner decision E stands; the homepage/empty-state strip is a later slice.
- **One counter event with the id as a suffix string.** Rejected: the enum is closed and server-validated; six entries beat a free-text suffix.

## Consequences

- Six new events on the counter; an OLD deployed server action rejects unknown events harmlessly, so a new client against an old deploy loses six counts and nothing else. The migration (028) is untouched.
- Every honesty scan is unchanged; the whole-card digit scan now really visits every panel tab (the first build's loop clicked every tab and scanned once — the whole-branch review caught it) in Dutch and English.
- Six `resolvePresentation` calls per panel render for the thumbnails — negligible next to the Recharts re-render the same click triggers.
- Residuals recorded, not fixed: the thumb's gradient rotates about the bounding-box origin rather than through `gradientEndpoints` (cosmetic at 64×40); the line-weight mapping collapses four widths into two in the thumb; a deterministic gradient id per template (one gallery mounted at a time); `sameValue` could compare `seriesColors` per index so an account default with colours beyond index 7 would still mark Klassiek.

## Revisit triggers

- Counter data (`template_*` vs `panel_open`, once 028 is applied) shows readers reaching for templates first → open the panel on the Templates tab.
- `template_applied` usage justifies saved named templates per account (a migration, supervised) or starter charts (v2).
- A brand-keyed team wants Brand as a real template with the key gating on this tab → move the Colours tab's reason here.
